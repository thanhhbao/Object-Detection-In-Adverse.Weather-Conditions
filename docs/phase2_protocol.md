# Phase 2 Protocol — RT-DETR-L Final Fine-Tune

Phase 2 trains **one single model, RT-DETR-L**. "Merge 3" refers to merging **three
datasets** (XWOD + ACDC + BDD100K) into one training set — it does not mean training
three models.

## 1. Why RT-DETR-L was selected

Stage 2 (fine-tuned from Stage 1 BDD100K weights on XWOD) was benchmarked across four
detectors. Model selection is based **primarily on Stage 2 XWOD validation performance**,
not on test-set ranking:

Stage 2 XWOD val mAP50-95:

| Model | mAP50-95 |
|---|---|
| RT-DETR-L | 0.559 |
| YOLO11n | 0.506 |
| YOLOv8n | 0.503 |
| Faster R-CNN | 0.421 |

RT-DETR-L has the best validation mAP50-95, so it is the single model carried into
Phase 2. XWOD test / DAWN test / BDD test results (see `docs/RESULTS.md`) may be reported
as held-out benchmark numbers, but they are **not** the model-selection criterion.

## 2. Phase 2 goal

Jointly fine-tune the Stage 2 RT-DETR-L checkpoint
(`stage2_xwod_rtdetr_from_bdd30k/weights/best.pt`) on a merged training set that combines
XWOD train, ACDC train, and the **full** BDD100K train split, to improve adverse-weather
robustness while retaining the clear-weather driving domain learned in Stage 1/2.

This is **not** a small-replay experiment — the full 30000-image BDD30K train split is
intentionally included, not a 2000-image subsample.

## 3. Training composition

Merged train set (`phase2_merged`), built by `scripts/build_phase2_dataset.py`:

| Source | Split | Images |
|---|---|---|
| XWOD | train | 6006 |
| ACDC | train | 1182 |
| BDD100K | train (**full**) | 30000 |
| **Base total** | | **37188** |

BDD intentionally dominates the base merge (30000 vs. 7188 adverse-weather images) — this
is expected and correct for the official protocol, not a bug to warn about.

## 4. Rare-class oversampling (train only)

Applied only to the merged train split, after the base merge, never to validation:

- bicycle ×2
- motorcycle ×3
- bus ×3
- all other classes ×1

Final train count = `37188 + <duplicate images generated by oversampling>`. This number
is derived from the actual labels at build time — it is not hard-coded anywhere in the
pipeline or in preflight.

## 5. Validation

Validation = **XWOD val only** (1001 images). No other split is used for early stopping or
model selection during Phase 2.

## 6. Test sets are never used for optimization

None of the following are ever included in Phase 2 training or validation:
XWOD test, ACDC val, ACDC test, DAWN val, DAWN test, BDD val, BDD test.

## 7. Build the merged dataset (Vast.ai)

```bash
bash scripts/build_phase2_vast.sh
```

Equivalent to:

```bash
python scripts/build_phase2_dataset.py \
  --xwod-root /workspace/datasets_noleak/xwod_6cls_yolo \
  --acdc-root /workspace/datasets_noleak/acdc_6cls_yolo \
  --bdd-root /workspace/datasets_noleak/bdd100k_6cls_yolo \
  --out-root /workspace/datasets_noleak/phase2_merged_yolo \
  --bdd-use-all \
  --seed 42 \
  --mode symlink \
  --oversample-rare \
  --clean
```

`--bdd-use-all` is the OFFICIAL Phase 2 mode: it takes every valid BDD train image/label
pair, unshuffled and untruncated. `scripts/build_phase2_dataset.py` also keeps a legacy
`--bdd-replay-images` / `--bdd-replay-ratio` sampling mode for backward compatibility with
earlier ablations, but that legacy mode is **not** used for the official Phase 2 build.

## 8. Preflight (run before spending any GPU time)

```bash
export OD_PATHS=configs/common/paths_vast.yaml
python scripts/preflight_phase2.py \
  --config configs/ultralytics/phase2_final_rtdetr_from_xwod.yaml
```

`scripts/build_phase2_vast.sh` runs this automatically after the build. Preflight hard-fails
(non-zero exit) if the resolved config or built dataset deviates from the official protocol
— including dataset key, `from_run`, batch, lr0, seed, checkpoint resolution, class order,
exact per-source image counts (6006 / 1182 / 30000 / 1001), the 37188 base-train invariant,
oversampling settings, broken symlinks, or any train/val source-split leakage.

## 9. Train

```bash
bash scripts/train_phase2_rtdetr_vast.sh
```

Equivalent to:

```bash
export OD_PATHS=configs/common/paths_vast.yaml
python scripts/train_ultralytics.py \
  --config configs/ultralytics/phase2_final_rtdetr_from_xwod.yaml
```

Config: `configs/ultralytics/phase2_final_rtdetr_from_xwod.yaml`
(`from_run: stage2_xwod_rtdetr_from_bdd30k`, `dataset: phase2_merged`, `batch: 16`,
`lr0: 0.00005`, `patience: 20`; `epochs`, `imgsz`, `optimizer`, `seed`, `deterministic`,
`amp`, `cos_lr` are inherited from `configs/common/train_defaults.yaml`).

## 10. Final evaluation protocol (after Phase 2 training only)

Run separately on all four held-out test sets — none of them were used during training:

- XWOD test
- ACDC test
- DAWN test
- BDD test

```bash
python scripts/evaluate.py \
  --config configs/ultralytics/phase2_final_rtdetr_from_xwod.yaml \
  --split test --data /workspace/datasets_noleak/xwod_6cls_yolo/dataset.yaml \
  --metrics-tag xwod_test

python scripts/evaluate.py \

  --split test --data /workspace/datasets_noleak/acdc_6cls_yolo/dataset.yaml \

python scripts/evaluate.py \
```

## 11. ACDC pre-Phase-2 baseline

Phase 2 trains on ACDC train, so improvement on ACDC test can only be measured against a
**pre-Phase-2 baseline**: the Stage 2 RT-DETR-L checkpoint evaluated on ACDC test, before
Phase 2 ever sees ACDC train.

```bash
export OD_PATHS=configs/common/paths_vast.yaml
python scripts/evaluate.py \
  --config configs/ultralytics/stage2_xwod_rtdetr_from_bdd30k.yaml \
  --split test --data /workspace/datasets_noleak/acdc_6cls_yolo/dataset.yaml \
  --metrics-tag acdc_test_baseline
```

This is a **PRE-PHASE-2 baseline**. It must not use ACDC train — it only evaluates the
Stage 2 checkpoint, which has never seen any ACDC data.

## Notes

- Phase 2 performs joint fine-tuning on XWOD train, ACDC train, and the **full** BDD30K
  train split (30000 images) — this is not a 2000-image BDD replay experiment, and BDD is
  not a "small minority" here.
- Including the full BDD train split helps retain the BDD driving domain during this final
  multi-domain fine-tune, alongside the adverse-weather data.
- Phase 2 is performed **only** on the selected RT-DETR-L checkpoint, not on YOLOv8n,
  YOLO11n, or Faster R-CNN — "merge 3" means three datasets, not three models.
- Test sets (XWOD test, ACDC test, DAWN test, BDD test) are never used for training, early
  stopping, or model selection.
- No Phase 2 result is claimed here — Phase 2 has not been trained yet. This document only
  fixes the reproducible protocol.
